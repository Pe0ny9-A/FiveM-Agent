# 玄玑 v0.9.1 — 三家 Provider 各自专精 + 上下文自动压缩

> 0.9.0 之前 DeepSeek 与 OpenAI 共用一个 Provider，DeepSeek thinking 模型多轮
> 对话第二轮会报 `BadRequestError 400 — The reasoning_content in the thinking
> mode must be passed back to the API`。0.9.1 把三家 Provider 拆开各自专精，
> 顺手把 thinking budget / prompt cache / 上下文压缩做成一等公民。

## 升级

```bash
pip install -U xuanji-fivem
# 或 uv tool upgrade xuanji-fivem
```

API 没有 breaking change。`xuanji version` 应当显示 `0.9.1`。

## 这一版做了什么

### 1. 修 DeepSeek thinking 模型多轮 400 报错

根因：之前 OpenAIProvider 既要兼容 OpenAI 又要兼容 DeepSeek，message 编码层
把 ThinkingBlock 直接丢了。DeepSeek 的 v4-pro / v4-flash / reasoner 在
thinking 模式下要求 `reasoning_content` 必须往返——上一轮姐姐想了什么，
下一轮要原样写回 assistant 消息的 `reasoning_content` 字段。

新建 [xuanji/llm/providers/deepseek.py](xuanji/llm/providers/deepseek.py) 独立
Provider：

- `chat()` 解析时把 `msg.reasoning_content` 抽成 `ThinkingBlock` 加在 blocks 最前
- `_to_deepseek_messages()` 编码 assistant 消息时把 `ThinkingBlock` 文本写回
  `reasoning_content` 字段
- `stream()` 分发 `thinking_start / thinking_delta / thinking_end` 事件，
  thinking 段先于 text/tool 段输出
- `prompt_cache_hit_tokens` 计入 `Usage.cache_read_tokens`

### 2. 三家 Provider 各自专精

每家有自己的独门特性，硬塞进通用层会污染其它端点。0.9.1 拆成三家：

| Provider | 一等公民 |
|---|---|
| Anthropic | `thinking_budget=N` 一参展开 Extended Thinking 配置 + 自动 `temperature=1`；`cache_system=True` 自动把 system 包成 `cache_control` ephemeral 块 |
| OpenAI | `_is_reasoning_model()` 识别 o1/o3/o4/gpt-5 系列，自动把 `max_tokens` 迁到 `max_completion_tokens`；自动 prefix cache 命中计入 Usage |
| DeepSeek | `reasoning_content` 双向往返；`prompt_cache_hit_tokens` 计量；thinking 流式分段 |

`factory.py` 路由：

```python
DeepSeekProfile → DeepSeekProvider          # 不再共用 OpenAIProvider
OpenAIProfile / OpenAICompatibleProfile → OpenAIProvider
AnthropicProfile → AnthropicProvider
```

### 3. 自动识别带缓存的模型

[Conductor](xuanji/neural/conductor.py) 每轮 model 请求前查
`provider.capabilities(model).supports_prompt_cache`：

- Anthropic 模型 → 自动注入 `cache_system=True`，system prompt 走 ephemeral cache
- OpenAI / DeepSeek → 自动 prefix cache 由后端实现，无需参数

未来加新模型时只要在 `_KNOWN_CAPS` 里登记 `supports_prompt_cache=True`，
Conductor 自动启用。

### 4. 上下文自动压缩

新模块 [xuanji/neural/compaction.py](xuanji/neural/compaction.py)。
当 history 估算超过 `max_context_tokens` 时，把头部对话折叠成一段
`[历史摘要]` 标记的 user 消息，保留尾部最近 N 轮原文：

```python
class CompactionConfig(BaseModel):
    enabled: bool = True
    max_context_tokens: int = 80_000        # 触发阈值
    keep_recent_turns: int = 4              # 末尾保留多少轮
    summary_per_turn_chars: int = 240       # 单轮摘要预览长度
```

设计取舍：

- **不调 LLM 做摘要**：第一版用规则提取（前 240 字 + 工具调用名清单），
  零依赖，不引入额外 token 成本
- **切点必须落在 user 消息上**：不会把 `tool_call` 与 `tool_result` 劈开
- **ThinkingBlock 不进摘要**：下一轮 reasoning 模型会重新生成
- **token 估算用 4 char ≈ 1 token**：足够用于触发判定

小宝可以在 `config.json` 调阈值：

```json
{
  "compaction": {
    "enabled": true,
    "max_context_tokens": 60000,
    "keep_recent_turns": 6
  }
}
```

或全关：`{"compaction": {"enabled": false}}`。

### 5. Conductor 累积 ThinkingBlock 到 history

`asst_blocks` 类型扩展为 `list[TextBlock | ThinkingBlock | ToolCallBlock]`，
把流式 `thinking_delta` 累积进 history。这是 DeepSeek `reasoning_content`
往返的前置条件，对 Anthropic Extended Thinking 也同样受益。
