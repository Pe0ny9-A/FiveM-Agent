# 玄玑 v0.9.2 — 项目宪法 XUANJI.md + 对话状态栏

> 进哪个项目就读哪个项目的 XUANJI.md，权重高于用户级偏好。
> CLI 对话每轮都给一份"模型 + token + ctx + 模式"状态栏，所有对话上下文一眼看完。

## 升级

```bash
pip install -U xuanji-fivem
# 或
uv tool upgrade xuanji-fivem
```

API 没有 breaking change。`xuanji version` 应当显示 `0.9.2`。

## 这一版做了什么

### 1. 项目级 XUANJI.md（项目宪法）

每个 FiveM 项目可以放一份 `XUANJI.md`——玄玑进哪个目录就读哪个，权重高于用户级。
专治"这个项目用 QBox 不是 QBCore"反复要再说一遍的痛点。

新模块 [xuanji/persona/project_memory.py](xuanji/persona/project_memory.py)：

- 从 cwd 沿目录树最多 12 层向上找 `XUANJI.md`，命中即停
- 用户级 fallback 在 `config_dir() / XUANJI.md`
- **优先级**：用户级先注入 → 项目级后注入（model 对靠后的 prompt 更敏感）
- 在 `Conductor.__init__` 启动期采集一次缓存，每条消息前都拼到 system prompt extras 里

CLI 子命令族 `xuanji project`：

```bash
# 在当前 cwd 写 XUANJI.md 模板（detector 自动填好 framework/inventory/target）
xuanji project init

# 已存在时拒绝覆盖；显式 --overwrite 才允许
xuanji project init --overwrite

# 检查当前项目载入了什么
xuanji project show

# 列出查找路径与命中位置
xuanji project path

# $EDITOR 打开编辑（Windows 兜底 notepad）
xuanji project edit
```

也可以直接和玄玑说"帮我熟悉这个项目"，它会主动调 `init_project_memory` 工具
（RiskTag.IO，覆盖既有需 `overwrite=true`）。

模板长这样：

```markdown
# 玄玑 · 项目记忆

## 项目身份
- **项目名**：my-bank
- **类型**：FiveM resource
- **Framework**：qbox
- **Inventory**：ox_inventory
- **Target**：ox_target

## 关键约定
- （命名、目录、依赖约束）

## 玄玑该怎么做
- 默认 framework：**qbox**

## 玄玑不该做
- （禁区）
```

### 2. CLI 对话底部状态栏

每轮对话回复后渲染一行紧凑状态栏：

```
  claude-sonnet-4-6@anthropic  ·  本轮 in 1.2k  out 567  cache 8.9k↓  ·
  累计 7.0k (in 5.0k / out 2.0k / cache 12.0k)  ·  ctx 12% (10.1k/80.0k)  ·
  3 轮  ·  8 msg  ·  chat/balanced  ·  think off  ·  default
```

包含：

- **模型 / provider**：当前路由到哪个端点
- **本轮 token**：input / output / cache_read↓ / cache_write↑
- **累计 token**：会话开始至今总计
- **ctx 占用百分比**：按 `compaction.max_context_tokens` 算（绿/黄/红三档）
- **轮数 / history 长度**
- **persona mode/temperature**：chat 模式下的语气档位
- **think on/off**：思维链是否显示
- **profile 名**：当前激活的 profile

`_format_tokens` 大数字带 k/M 后缀让一行装得下。

### 3. 新斜杠命令

- **`/stats`** — 任何时候拉出最新统计（不消耗 LLM 调用）
- **`/think on|off`** — 切换思维块显示，状态会落 `chat_ui.show_thinking` 跨会话保留
- **`/forget`** — 清掉磁盘上的会话快照

### 4. 会话恢复

退出对话时写 `last_session.json` 快照，下次启动若 profile/model 一致，
会问"恢复上次的对话？"，回车默认是。

不一致时（比如换了 provider）会跳过恢复，避免 thinking 块灌错端点。

### 5. 修循环导入

新增 `xuanji/persona/project_memory.py` 引入了
`Conductor → persona → config → store → compaction → neural → conductor`
的循环。解法：把 `from xuanji.persona.project_memory import ...` 移到
`Conductor.__init__` 方法体内做延迟 import，等 module 全加载完再触发。
