# 玄玑 v0.9.0 — 工具工厂闭环

> 0.2 起 `propose_tool` 就在了，但从「玄玑写草案」到「真能用的工具」中间断了
> 一截。0.9 把这截补上：generate / test / publish / reject 全部上 CLI，
> ServerRuntime 启动期自动扫 `tool_published/` 目录加载。
>
> 同时死守一条线——玄玑只能写草案，**不能**触发后面任何步骤。

## 升级

```bash
# 先升包
pip install -U xuanji-fivem
# 或 uv tool upgrade xuanji-fivem
```

API 没有 breaking change。`xuanji version` 应当显示 `0.9.0`。

## 这一版做了什么

### 1. CLI 工厂四件套

之前只有 `xuanji tool drafts` 看草案、`xuanji tool list` 看注册表，闭环卡在
generate/test/publish 三步全得人工。0.9 把它们都做成 CLI：

```bash
# 1. 玄玑在对话里调 propose_tool 写草案
#    → ~/.local/share/xuanji/tool_drafts/<slug>.json

# 2. 小宝 review 后让玄玑跑代码生成
xuanji tool generate <slug>
# → 用激活 profile 的 LLM，按草案生成 Tool 子类 + pytest 单测
# → 落到 tool_staged/<slug>.py + test_<slug>.py

# 3. subprocess 跑单测
xuanji tool test <slug>
# → 通过：status → tested
# → 不通过：status 留在 generated，pytest 输出回显

# 4. 拍板发布
xuanji tool publish <slug>
# → 门控：status 必须是 tested
# → 复制到 tool_published/<slug>.py

# 也可以直接拒
xuanji tool reject <slug> --reason "schema 不合"

# 看注册表
xuanji tool status              # 全部 slug
xuanji tool status <slug>       # 单个详情含最近一次 pytest 输出
```

### 2. published 动态加载

新模块 [xuanji/tools/published_loader.py](https://github.com/Pe0ny9-A/FiveM-Agent/blob/main/xuanji/tools/published_loader.py)：

- `load_published_tools(published_dir)` 扫所有 `*.py`
- `importlib` 动态 load 到独立命名空间 `xuanji.tools.published.<slug>`，不污染项目 import 路径
- `inspect.getmembers` 找在本模块**直接定义**的 `Tool` 子类（避开从 base 拉进来的基类被实例化）
- 必须 `cls()` 无参数实例化才接受——内置工具靠 `__init__` 注入依赖，published 这层只支持自包含工具
- **单文件失败不连坐**：一个坏工具只 logger.warning 跳过，不会让整个启动卡死

`ServerRuntime.build_registry()` 在工厂工具之后接入 published：

```python
registry.register_all(tool_factory_tools(tool_drafts_dir()))
for published in load_published_tools(tool_published_dir()):
    with contextlib.suppress(ValueError):
        registry.register(published)
```

`ValueError` suppress 是为同名冲突——内置工具优先，published 同名静默跳过。

### 3. 安全核心：玄玑写不了代码到 published

四步流水线刻意让 LLM 卡在第一步：

```
玄玑 LLM ──propose_tool──▶ tool_drafts/<slug>.json    ← 唯一 LLM 能做的
                              │
                              │  小宝 review
                              ▼
                       xuanji tool generate           ← CLI，不在玄玑工具集
                              │
                              ▼
                       tool_staged/<slug>.py
                              │
                       xuanji tool test               ← CLI，subprocess pytest
                              │  → status="tested"
                              ▼
                       xuanji tool publish            ← CLI，门控 status=="tested"
                              │
                              ▼
                       tool_published/<slug>.py       ← 下次启动才生效
```

四个 CLI 命令都不挂在玄玑的工具注册表里——LLM 无法在对话里把它们当工具调。
generate 跑 LLM 这步即便被注入恶意 prompt，落地的也只是 staged 代码，
没跑 test 不能 publish，跑 test 在 subprocess 里隔离。

## 升级后试试

跟玄玑说一句这种话就能验证流水线：

> 我想要个工具能解析 fxmanifest.lua 提取 shared / client / server 三段脚本路径，
> 调一下 propose_tool 写个草案

然后：

```bash
xuanji tool drafts                            # 看草案
xuanji tool drafts --show parse_fxmanifest    # 看完整 JSON
xuanji tool generate parse_fxmanifest         # 跑 codegen
xuanji tool test parse_fxmanifest             # 跑单测
xuanji tool publish parse_fxmanifest          # 拍板
# 退出当前会话，重新 xuanji chat → 玄玑工具列表里多了 parse_fxmanifest
```
